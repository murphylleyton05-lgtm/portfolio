Página 1 · Arquitectura completa del lienzo (n8n)

Circuito híbrido de persistencia (Lectura → Filtro → Escritura), aislado por Session_ID: se lee la memoria por ID; un IF separa usuarios nuevos (crea registro limpio, sin variables vacías) de recurrentes (inyecta el contexto en el System Prompt). Al superar 5 mensajes, un LLM económico consolida la charla en un JSON limpio que sobrescribe el registro de forma idempotente. Nunca se vuelcan HTML, logs ni transcripciones completas a la base.
Implementación real y probada. Flujo construido y ejecutado en n8n Cloud (workflow ID P2rHab3kLg3SmlbI). Los diagramas son fieles al lienzo real y los datos de las páginas 2–3 provienen de ejecuciones reales. La base de memoria se implementó con la Data Table nativa de n8n (persistencia sin credenciales), equivalente 1:1 a Airtable en columnas y tipos.

Página 2 · Prompt de summarization (salida JSON forzada)

Nodo Summarization (Resumen JSON) — Basic LLM Chain con modelo económico GPT-4o-mini (temperatura 0) y un Structured Output Parser que obliga el esquema. Se activa solo cuando message_count > 5.

System Message (prompt exacto usado en el modelo mini)

Sos un modulo de summarization de contexto. Recibis el resumen previo de una
sesion y el ultimo intercambio (usuario + asistente). Tu UNICA tarea es devolver
un objeto JSON valido, sin texto adicional, sin markdown y sin comillas de codigo,
con EXACTAMENTE esta forma:
{ "asunto_principal": string, "puntos_clave": array de strings, "accion_requerida": string }
REGLAS ESTRICTAS:
- "asunto_principal": una frase que consolide el estado actual del caso del usuario.
- "puntos_clave": entre 2 y 5 hechos duros, accionables y no redundantes.
- "accion_requerida": el proximo paso concreto a realizar.
- PROHIBIDO incluir HTML, logs tecnicos, payloads o transcripciones completas.
- Se breve, factual y en espanol neutro.

User Message (historial que se envía, con expresiones nativas de n8n)

Resumen previo de la sesion:
{{ $('Contexto listo').item.json.last_summary }}

Nuevo intercambio a integrar:
Usuario: {{ $('Contexto listo').item.json.chatInput }}
Asistente: {{ $json.output }}

Esquema de salida forzado (Structured Output Parser)

{
  "asunto_principal": "string",
  "puntos_clave": [ "string", "..." ],
  "accion_requerida": "string"
}
Salida real generada en una ejecución (guardada en la columna resumen_consolidado, sobrescribiendo el registro de forma idempotente):
{
  "asunto_principal": "Lleyton busca roles de Data Analyst remoto en LATAM con salario publicado.",
  "puntos_clave": [
    "Interés en roles de Data Analyst remoto",
    "Preferencia por zona horaria LATAM",
    "Salario publicado es un requisito"
  ],
  "accion_requerida": "Revisar las vacantes proporcionadas y seleccionar las de interés."
}

Página 3 · Esquema de la base de memoria

Base relacional de memoria de largo plazo, aislada por Session_ID. Implementada como Data Table de n8n (portable a Airtable con idénticas columnas y tipos). Un registro por sesión; se lee al inicio y se sobrescribe al cierre.

Columnas y tipos

ColumnaTipoDescripción / metadato
session_idstringIdentificador único de sesión. Clave de aislamiento: filtra el registro exacto y blinda contra la amnesia cruzada.
user_namestringNombre del usuario, recuperado e inyectado en el System Prompt.
fecha_actualizacionstring (ISO 8601)Timestamp de la última escritura (para auditoría / orden).
resumen_consolidadostring (JSON)Objeto {asunto_principal, puntos_clave, accion_requerida} de la summarization. Es el "last_summary" que se reinyecta.
estado_del_casostringEstado / próxima acción del caso (Status).
datos_clavestring (JSON)Array de hechos duros y accionables (puntos_clave). Nunca transcripciones ni payloads pesados.
message_countnumberContador de intercambios de la sesión. Dispara la summarization al superar 5.
id · createdAt · updatedAtsystemMetadatos automáticos de la Data Table (clave primaria y timestamps de fila).
